================================================================================
                              AUTHENTICATION
================================================================================

The API uses HMAC-SHA256 authentication for the /v1/ingest endpoint.

Required Headers:
  X-API-Key: Your API key (obtained from /developers/:id/api-keys)
  X-Signature: HMAC-SHA256 signature of the request body using the API key

Signature Calculation:
  1. Take the raw JSON request body
  2. Compute HMAC-SHA256 using your API key as the secret
  3. Hex-encode the result
  4. Set as X-Signature header

================================================================================
                           REVENUE SHARING MODEL
================================================================================

The platform uses a developer-configurable revenue sharing model:

  - Platform:   5% (fixed infrastructure fee)
  - Users:      50-90% (configurable by developer, default 70%)
  - Developers: Remainder (100% - 5% - user_share)

Developer Competitive Advantage:
  - Developers can set higher user shares (up to 90%) to attract more users
  - Higher user share = better visibility in marketplace search
  - This creates healthy competition benefiting users

Example Configurations:
  - Default:   User 70%, Developer 25%, Platform 5%
  - Generous:  User 85%, Developer 10%, Platform 5%
  - Minimum:   User 50%, Developer 45%, Platform 5%

Micro-Payment Handling:
  - Amounts below $0.01 are held in "pending_balance"
  - When pending_balance reaches $0.01, it's released to available balance
  - This ensures fair distribution even with many users

Earnings Formula:
  Total = quality_score × (active_seconds / 3600) × hourly_rate
  User Earnings = Total × user_share_percent%
  Developer Earnings = Total × (100 - 5 - user_share_percent)%
  Platform Fee = Total × 5%

CONFIGURATION
--------------------------------------------------------------------------------

GET /config/revenue-shares
  Returns default revenue sharing configuration.
  Note: Actual shares depend on developer's configured user_share_percent.
  
  Response 200:
    {
      "user_share_percent": 70,
      "developer_share_percent": 25,
      "platform_fee_percent": 5,
      "min_payout_threshold": 0.01

--------------------------------------------------------------------------------
USERS
--------------------------------------------------------------------------------

POST /users
  Create a new user.
  
  Request Body:
    {
      "email": "user@example.com",
      "name": "John Doe",
      "password": "SecurePass123!"
    }
  
  Response 201:
    {
      "id": "uuid",
      "email": "user@example.com",
      "name": "John Doe"
    }

GET /users/:id
  Get user by ID.
  
  Response 200:
    {
      "id": "uuid",
      "email": "user@example.com",
      "name": "John Doe"
    }

--------------------------------------------------------------------------------
DEVELOPERS
--------------------------------------------------------------------------------

POST /developers
  Register a new developer.
  
  Request Body:
    {
      "name": "My Company",
      "email": "dev@company.com",
      "password": "SecurePass123!"
    }
  
  Response 201:
    {
      "id": "uuid",
      "name": "My Company",
      "email": "dev@company.com",
      "user_share_percent": 70,
      "dev_share_percent": 25
    }

GET /developers/:id
  Get developer by ID.
  
  Response 200:
    {
      "id": "uuid",
      "name": "My Company",
      "email": "dev@company.com",
      "user_share_percent": 70,
      "dev_share_percent": 25
    }

PUT /developers/:id/user-share
  Update developer's user share percentage.
  Higher user share = more attractive to users = better marketplace visibility.
  
  Request Body:
    {
      "user_share_percent": 85
    }
  
  Validation:
    - user_share_percent must be between 50 and 90
  
  Response 200:
    {
      "id": "uuid",
      "name": "My Company",
      "email": "dev@company.com",
      "user_share_percent": 85,
      "dev_share_percent": 10
    }
  
  Error 400 (invalid percentage):
    {
      "error": "user share must be between 50% and 90%"
    }

POST /developers/:id/api-keys
  Generate a new API key for a developer.
  
  Request Body:
    {
      "name": "Production Key"
    }
  
  Response 201:
    {
      "id": "uuid",
      "key_prefix": "abc12345",
      "name": "Production Key",
      "is_active": true,
      "raw_key": "full-api-key-only-shown-once"
    }
  
  IMPORTANT: The raw_key is only returned once. Store it securely.

GET /developers/:id/api-keys
  List all API keys for a developer.

DELETE /developers/:id/api-keys/:keyId
  Revoke an API key.

WALLETS
--------------------------------------------------------------------------------

POST /wallets
  Create a new wallet.
  
  Request Body:
    {
      "owner_id": "uuid",
      "type": "user|developer|buyer|faucet|platform",
      "currency": "USD"
    }
  
  Response 201:
    {
      "id": "uuid",
      "owner_id": "uuid",
      "type": "user",
      "balance": 0,
      "pending_balance": 0,
      "currency": "USD",
      "created_at": "2024-01-01T00:00:00Z"
    }

GET /wallets/:id
  Get wallet by ID.
  
  Response 200:
    {
      "id": "uuid",
      "owner_id": "uuid",
      "type": "user",
      "balance": 100.50,
      "pending_balance": 0.00567823,
      "currency": "USD",
      "created_at": "2024-01-01T00:00:00Z"
    }

GET /wallets/owner/:ownerId
  Get all wallets for an owner.

POST /wallets/:id/credit
  Add funds to a wallet (available balance).
  
  Request Body:
    {
      "amount": 100.00
    }

POST /wallets/:id/debit
  Remove funds from a wallet.
  
  Request Body:
    {
      "amount": 50.00
    }
  
  Error 400 (insufficient balance):
    {
      "error": "insufficient balance"
    }

POST /wallets/:id/release-pending
  Release pending balance to available if threshold is met.
  
  Response 200:
    {
      "status": "processed",
      "released": 0.02
    }

--------------------------------------------------------------------------------
DATA INGESTION (AUTHENTICATED)
--------------------------------------------------------------------------------

POST /v1/ingest
  Ingest raw sensor data. Requires HMAC authentication.
  
  Headers:
    X-API-Key: your-api-key
    X-Signature: hmac-sha256-signature
    Content-Type: application/json
  
  Request Body:
    {
      "event_id": "uuid",
      "timestamp": 1704067200000,
      "type": "sensor_data",
      "data": {
        "accelerometer": [...],
        "gyroscope": [...],
        "touch_events": [...]
      }
    }
  
  Response 202:
    {
      "status": "accepted",
      "event_id": "uuid"
    }

================================================================================
                           ERROR RESPONSES
================================================================================

All endpoints may return the following error formats:

400 Bad Request:
  {
    "error": "invalid request body"
  }

401 Unauthorized:
  {
    "error": "missing X-API-Key header"
  }

404 Not Found:
  {
    "error": "resource not found"
  }

422 Unprocessable Entity (Validation Error):
  {
    "error": "validation_failed",
    "message": "Request validation failed",
    "errors": [
      {
        "field": "email",
        "message": "email must be a valid email address",
        "tag": "email",
        "value": "invalid-email"
      }
    ]
  }

500 Internal Server Error:
  {
    "error": "internal server error"
  }

   go run cmd/api/main.go

3. Run tests:
